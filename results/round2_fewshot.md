# CS6140 第二轮：闭源模型（Claude）提升方法对比

日期：2026-11-14
模型：Claude Opus 5.5，effort low，通过 Claude Code CLI 调用（走订阅，不扣钱）
测试集：ar、zh、fr、de 四个语言对，每个 800 条（400 切换 / 400 不切换），共 3,200 条；三种方法用的是完全相同的位置。
代码：本地分支 `round2-fewshot`（**还没 push**，main 没动）。

## 结论

**Few-shot 是最好的方法：准确率从 74.9% 提到 89.4%，F1 从 69.8% 提到 89.3%，每次调用的成本还比 baseline 低。**
概率 + 调阈值没有效果。

## 总表（四个语言对合并）

| 方法 | 准确率 | F1 | 精确率 | 召回率 | token/次（输入 + 输出） | API 等价成本/次 |
|---|---|---|---|---|---|---|
| Baseline（直接判切不切） | 74.9% | 69.8% | 87.8% | 57.9% | 868 + 34 | $0.0076 |
| 概率 + 交叉验证调阈值 | 66.8% | 70.2% | 63.7% | 78.1% | 892 + 43 | $0.0080 |
| **Few-shot（8 个例子）** | **89.4%** | **89.3%** | **90.6%** | **88.0%** | 1,835 + 39 | **$0.0061** |

- 概率法的 AUROC 是 0.772（ar 0.740 / zh 0.848 / fr 0.761 / de 0.720）。
- 成本是 CLI 返回的「如果按 API 计费」的价格。Few-shot 输入翻倍却更便宜，是因为 8 个例子放在 system prompt 里，被缓存了：平均每次约 1,343 个 token 按缓存价读取。直接调 API 且不开 prompt caching 的话，few-shot 会比 baseline 贵，大约是 2 倍输入。
- Baseline 的 token 数取自后补跑的 1,600 条，前 400 条跑的时候还没有记录 token。

## 推算：如果跑全量，结果会是什么

全量 = 四个语言对里所有标签可信的位置，共 **1,675,068 个**，真实切换率 **10.2%**（ar 13.6% / zh 7.5% / fr 11.2% / de 12.4%）。没有再调模型：把 800 条样本里每一组（语言对 × 当前词是否英文 × 是否切换）测到的命中率 / 误报率，按全量里这一组的位置数重新加权。括号是 bootstrap 95% 置信区间。脚本：`python cs_extrapolate.py`。

| 方法 | | 准确率 | 精确率 | 召回率 | F1 |
|---|---|---|---|---|---|
| Baseline | 800 平衡样本（上表） | 74.9% | 87.8% | 57.9% | 69.8% |
| Baseline | **推算全量** | **88.8%** (87.4–90.2) | **46.3%** (41.7–51.6) | **62.0%** (59.8–64.2) | **53.0%** (49.7–56.3) |
| Few-shot | 800 平衡样本（上表） | 89.4% | 90.6% | 88.0% | 89.3% |
| Few-shot | **推算全量** | **90.5%** (89.0–91.9) | **52.0%** (47.6–56.5) | **88.3%** (86.6–89.8) | **65.5%** (61.8–69.0) |

按语言对的推算全量 F1：

| 语言对 | Baseline | Few-shot |
|---|---|---|
| ar | 53.3% | 63.2% |
| zh | 51.8% | 59.5% |
| fr | 55.0% | 75.5% |
| de | 53.1% | 73.2% |

- **全量下 F1 会明显下降**（few-shot 89% → 约 65%）：约 90% 的位置不切换，误报率只有约 9%，但误报的绝对数量已经和真切换差不多，精确率掉到 50% 左右。
- **Few-shot 仍然明显更好**：F1 高 12.5 个点，置信区间不重叠，召回从 62% 提到 88%。代价是报警更多：每 1 个真切换，baseline 报 1.34 次，few-shot 报 1.70 次。
- **全量下准确率不能当主指标**：永远预测「不切换」就有 89.8% 准确率，baseline（88.8%）比它还低。全量部分应以 F1 / 精确率 / 召回率为主。
- 前提：模型在全量上每组的命中率和误报率跟样本一样。筛选条件相同（只算可信标签、前缀至少 5 个词），但长对话在全量里占的位置更多，所以这是估计值，不是实测值。

## 为什么 few-shot 有效：修好了 X→EN 方向

| 方法 | 召回 X→EN（1,017 条） | 召回 EN→X（583 条） | 误报率（不切换却判切换） |
|---|---|---|---|
| Baseline | 41.6% | 86.4% | 8.1% |
| Few-shot | **87.3%** | 89.2% | 9.1% |

第一轮最大的问题是从 X 语言切回英文的情况几乎一半都漏掉。Few-shot 把这个方向的召回从 42% 拉到 87%，误报只多了 1 个百分点。

## 为什么概率 + 调阈值没用

- 调阈值只能拿精确率换召回率：召回从 58% 升到 78%，但精确率从 88% 掉到 64%。
- 即使直接在测试集上挑最好的阈值（作弊上限），每个语言对的准确率也没超过 baseline。
- 模型给的概率很粗：fr、de 里约 210/800 条都给了 0.12，同一个分数里切和不切混在一起，阈值分不开。
- 说明瓶颈是模型的区分能力，不是判定门槛。

## 实现方式

- 例子来源：`python cs_sample.py --fewshot --pairs ar zh fr de`。每个语言对 8 个例子，四类各 2 个：X→EN 切换、EN→X 切换、留在 X、留在英文。都来自**不在测试集里**的对话（按对话 id 和文本去重），前文最长 300 字符。存在 `samples/fewshot_*.jsonl`。
- 运行：`python cs_predict.py run --provider claude-cli --model claude-opus-5-5 --effort low --method fewshot --pairs ar zh fr de`
- 评估：`python cs_predict.py eval --method fewshot --pairs ar zh fr de`

## 要注意的地方（写报告时）

1. **可能学到了数据集的套路。** SwitchLingua 是 LLM 生成的数据，切换常出现在句尾的 "you know?"、"right?" 这类附加语，或者换行后换语言。Few-shot 例子可能让模型学会了这些套路，而不是学会了真实的语码转换。所以提升里可能有一部分是「适应了这个数据集」。
2. **例子只抽了一次**（seed 7）。换一组例子结果可能有波动；想严谨的话可以换 2–3 个 seed 再跑。
3. **有 9 条 zh 回复无法解析**（1.1%），按「不切换」计分。原因是模型输出了推理文字而不是 JSON。
4. **持续时长（duration）预测没有变好**：few-shot 的 durF1 是 48–63%，baseline 是 58–64%，持平或略降。
5. 和 Qwen 那边不是同一个测试集，只能在 AUROC 上粗略对比。
